## Verified material findings

1. **Use the already-generated general quality flag as a baseline.** `newsly-providers/src/news_item.rs:30-36` instructs `to_read` for substantive reader value and `skip` only for duplicative, empty, promotional or otherwise low-signal items. This is not personalized relevance. `news_item/input.rs:452-465` serializes it to `raw_metadata.summary.classification`; `news_item/repository.rs:812-835` stores it and marks the item ready regardless of flag. News list/count/detail SQL in `newsly-db/src/content_read.rs:299,380` and Briefing `briefing_refresh/sources.rs:155` do not exclude flagged items. API presentation exposes it (`content_read/presentation.rs:970-977`), while iOS references found decode it without an admission filter. Inspect observed prevalence and false skips, then compare a rules policy using the flag against learned ranking; no additional inference is needed to read it.

2. **Include per-user pre-composition admission as a distinct option.** `seed_news_pending` is a useful seam after shared enrichment but before user-specific composition. Changing priority alone does not guarantee lower cumulative cost because later refreshes can admit the rest. Actual savings require an explicit bounded admission/reading policy and deferred/All reachability; do not promise the existing 40 batch is a daily budget. Composed segment reordering and pre-admission ranking are different product choices. Keep initial experiment offline, eventual model scores materialized, and immutable feed/rank generations for pagination.

3. **News open analytics has an identity-type mismatch in current code.** `ContentDetailViewModel.swift:199-200` loads News detail, then `:225-229` and `:421-431` sends that News ID to `trackContentOpened(contentId:)`. `ContentDetail.swift:221-223` preserves the response News ID. Server `mutations.rs:129-138` passes the numeric ID straight through, and `newsly-db/src/interactions.rs:66-75` validates it only against `contents`. A news open can therefore reject or identify an unrelated Content ID. Production incidence is unverified. Do not train from historical opens without auditing this; no bug fix is authorized by this research subtask.

4. **Regular feeds can miss bursts exceeding the cap.** Default feed selection stops after 10 unseen entries, while the next regular run stops at the first known URL (`scrape.rs:474,483-489`; `scraping/feed.rs:69-77`). With a newest-first feed containing 15 fresh items, first run stores 10, second run sees the now-known first item and stops before remaining five. Manual/backfill uses SkipKnown (`feed_backfill.rs:120`). This is a conditional code-traced missed-catchup case, not proof all feeds lose items permanently. Keep candidate discovery/cursors separate from processing budgets.

5. **All-news UI is not currently established.** Current app ContentView.swift:45-70 has only Briefing and Knowledge tabs. RootTabs.swift presents BriefingView or saved Knowledge/search. The remaining fetchNewsItemList callers found are its implementation and a bulk-mark helper in ContentService. The API supports chronological All, but deferred/All access needs an explicit app UX deliverable before admission policies hide material. No Simulator runtime claim was made.

## Rejected or qualified oracle claims

- **Rejected: cached lens vectors exist only for admitted pending items.** Oracle inspected the fallback ready_news path but missed eager warmup. News processing finalization queues `PrepareNewsLens` before ready fanout (`newsly-worker/src/news_item/repository.rs:394-405`). Scheduler also finds ready global representative items from last 7 days lacking current embeddings, up to 128, and queues warmup (`newsly-scheduler/src/repository/fanout.rs:114-136`). Thus no evidence for the claimed admission-only vector sample bias or claim that a new all-ready prewarming stage is inherently required. Actual cache coverage remains unmeasured, and source-cap/processing bias still exists.
- **Qualified: admission priority saves spend.** It may reduce/avoid per-user composition only with a deliberate stopping/defer policy; mere reordering does not. Shared news summary/extraction costs already occurred.
- **Qualified: feed items are lost for good.** Ordinary catchup can miss them; explicit backfill, reordering or later discovery can recover them. Use the narrower statement above.
- **Qualified: model thresholds and sample-size numbers.** Oracle's +15 percentage points, 80%-of-model-gain rules threshold, and minimum 40 test positives are proposed planning heuristics, not empirically validated Newsly gates. Report uncertainty and user slate preference without presenting them as universal requirements.
- **Qualified: current-batch event grouping is ground truth.** It uses embedding similarity plus title token overlap (`briefing_refresh/planning.rs:231-261`). It can help prevent leakage but needs review; it is distinct from identity deduplication and personal novelty.
- **Do not repeat unverified assertions:** 'roughly one user', exact deployed cache dimensions, universally negligible latency, live cost numbers or live classification distributions were not established by this local review.
