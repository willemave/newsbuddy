# migrations/

Source folder: `migrations`

## Purpose
Alembic migration tree for the PostgreSQL schema used by the FastAPI backend, workers, admin UI, and CLI-facing APIs.

## Runtime behavior
- `migrations/alembic.ini` points Alembic at `migrations/alembic`.
- `migrations/alembic/env.py` imports the app model metadata so autogenerated migrations see the SQLAlchemy tables from `app/models/db`.
- `migrations/alembic/versions/` contains chronological schema changes for users, content, processing tasks, chat, discovery/onboarding, search indexes, integrations, vendor usage, CLI links, feedback, discussions, audio episodes, and learning decks.
- Deployment bootstrap and local setup run `alembic -c migrations/alembic.ini upgrade head`.

## Important files
| Path | Purpose |
|---|---|
| `migrations/alembic.ini` | Alembic configuration rooted under this folder. |
| `migrations/alembic/env.py` | Migration environment, app metadata loading, and online/offline migration setup. |
| `migrations/alembic/script.py.mako` | Template for newly generated migration files. |
| `migrations/alembic/versions/` | Ordered revision scripts. |

## Integration points
- ORM table definitions live in `app/models/db`.
- Settings and DB URL resolution come from `app/core/settings.py` and `app/core/db.py`.
- Tests that need schema state use the repo test harness rather than applying migrations in each test.

## Notes
- Migration files are source. Pycache and local database files are runtime artifacts.
- When adding DB-backed behavior, update models, add a migration, and keep API/model docs aligned if the new state crosses API boundaries.
